## [0.12.0] — 2026-09-21
Module — Delivery workflow. See `docs/modules/10-delivery.md`.

### Added
- **Delivery pipeline** (`GET /deliveries`): confirmed/invoiced bookings with a computed stage — Ready · Scheduled · Overdue · Awaiting payment · Delivered — plus balance, expected date and pending documents (one company-scoped raw-SQL query with filter/search/pagination).
- **Scheduling** (`POST /deliveries/:id/schedule`): expected date + pending documents.
- **Completion** (`POST /deliveries/:id/complete`): reuses the existing `BookingsService.markDelivered` core (invoice + zero-balance guards, unit → Delivered, timeline, audit — no logic duplicated), then captures the handover checklist, notes and override reason.
- **Handover / pre-delivery checklist** — extended `DeliveryChecklist` to 10 items (keys, charged, charger, helmet, accessories, KYC docs, invoice, insurance, RC, warranty card); editable after delivery (`PATCH /deliveries/:id/checklist`).
- **Photos + customer signature** — image uploads via the shared `StorageService` (`POST /deliveries/:id/photos`, `/signature`; `DELETE …/photos/:photoId`).
- **Branded delivery note PDF** (`GET /deliveries/:id/note.pdf`) — vehicle, handover checklist, notes and signature lines, via `PdfBrandService`.
- **Delivery dashboard** KPIs (`GET /deliveries/dashboard`) + a `deliveries` **report** in the export architecture (PDF/Excel/CSV).
- **Frontend** `Delivery` section (nav enabled + `/delivery`): KPI strip, pipeline table with stage filter + search, and a detail dialog covering schedule → checklist → complete → photos/signature/note. Responsive + native-aware PDF.
- Security: Owner / Manager / Sales Executive. (Delivery notifications — overdue / due-today / pending-docs — were already generated by the notifications engine.)
- Tests: `delivery.e2e-spec.ts` (9): pipeline stage, schedule, complete-with-checklist (→ unit Delivered), double-complete guard, checklist edit, photo + signature upload (+ wrong-mime 400), delivery-note PDF, dashboard + report export, permission matrix. **75 unit + 132 e2e + 9 web** green.

## [0.11.0] — 2026-08-04
Module 9.1 — Finance enhancements. See `docs/modules/9-finance.md`.

### Added
- **Expense attachments** — upload Invoice / GST Bill / Photo / PDF (≤10 MB) via the shared storage abstraction (`ExpenseAttachment` model, S3-swappable `StorageService`); preview links + delete in a new expense detail dialog.
- **Approval workflow** — `ExpenseStatus` gains `DRAFT`; flow Draft → Pending → Approved → Paid (`POST /expenses/:id/submit`, existing approve/reject + settle). Create supports "Save as draft".
- **Recurring expenses** — `RecurringExpense` templates (rent, salary, subscriptions…) with `POST /finance/recurring/run` that generates the month's expenses idempotently (the seam a future scheduler calls); managed from a Recurring dialog.
- **GST summary** — `GET /finance/gst-summary` (collected vs paid vs net, with a monthly breakdown) + a GST tab and export.
- **Monthly closing** — `MonthlyClosing` locks a month; every finance mutation (expense/income/bank/adjustment create·update·delete) calls `assertOpen(date)` and 400s inside a locked month. Close/reopen from a Closing tab.
- **Bank reconciliation** — `BankTransaction.reconStatus` (Pending / Cleared / Reconciled) with `PATCH /bank-transactions/:id/reconcile` and an inline status control.
- Tests: 6 new finance e2e cases (attachments, approval, recurring idempotency, GST, closing lock/reopen, reconcile). **75 unit + 123 e2e + 9 web** green.
