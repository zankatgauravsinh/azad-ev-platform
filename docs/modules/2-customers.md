# Module 2 — Customer Domain

Status: **delivered**. The Customer Profile is the central entity every later module references (Booking, Sales, Delivery, Service all attach to it and append to its timeline).

## Delivered
- **Profile with tabs** — Overview, Timeline, Documents, Bookings, Payments, Deliveries, Service, Warranty, Notes, Activity Log.
- **Overview fields** — name, mobile, alt mobile, email, address, city, state, PIN, occupation, DOB, gender, lead source, assigned executive, preferred model/colour/finance, current status (+ lost reason).
- **Immutable timeline** — append-only `CustomerTimelineEntry`, auto-generated by the system (lead created, status changes, logged interactions, notes, documents, follow-ups). No edit/delete path. Supports type filtering. Future modules append via the exported `CustomerTimelineService`.
- **Follow-ups + reminders** — schedule (date/time, priority, reminder lead-time, note), complete/cancel; `GET /customers/follow-ups/reminders` buckets pending follow-ups into overdue / today / upcoming for the Dashboard.
- **Documents folder** — Aadhaar, DL, PAN, finance, insurance, invoice, warranty, delivery photos, signature, other. Preview, download, **replace**, delete (via `StorageService`).
- **Notes** — internal only; editing archives the previous version (`CustomerNoteRevision`), with a visible edit count and history viewer.
- **Lead management** — statuses New, Contacted, Interested, Test Ride, Negotiation, Booked, Won, Lost; Lost requires a stored reason.
- **Search** — name, mobile, email, and (via joins) VIN, booking code, invoice number.

## Data model
- `Customer` extended: state, pin, occupation, dateOfBirth, gender, preferredModel (relation), preferredColour, preferredFinanceOption, lostReason.
- New enums: `Gender`, `CustomerEventType`, `FollowUpPriority`, `FollowUpStatus`; `LeadStatus` gains `INTERESTED`.
- New tables: `CustomerTimelineEntry` (append-only), `CustomerFollowUp`, `CustomerNoteRevision`. Removed the unused `CustomerInteraction`.
- Shared: `UNIT_STATUS_TRANSITIONS` pattern mirrored by the lead lifecycle; `MANUAL_CUSTOMER_EVENTS` gates which timeline entries a user may log.
- Migration: `prisma/migrations/*_customer_domain`.

## API (under `/api/v1`, bearer auth; see Swagger `/api/docs`)
Aggregates: `GET /customers/stats`, `GET /customers/follow-ups/reminders`.
CRUD: `GET/POST /customers`, `GET/PATCH/DELETE /customers/:id`, `PATCH /customers/:id/status`.
Timeline: `GET /customers/:id/timeline?type=`, `POST /customers/:id/interactions` (log call/walk-in/test-ride/feedback/referral).
Profile tabs: `GET /customers/:id/related` (bookings/payments/deliveries/service/warranty), `GET /customers/:id/activity`.
Documents: `GET/POST /customers/:id/documents`, `PATCH /:docId` (replace), `DELETE /:docId`.
Notes: `GET/POST /customers/:id/notes`, `PATCH /:noteId`, `GET /:noteId/revisions`, `DELETE /:noteId`.
Follow-ups: `GET/POST /customers/:id/follow-ups`, `PATCH /:followUpId`, `POST /:followUpId/complete`, `POST /:followUpId/cancel`.

**Roles:** read & write = Owner, Manager, Sales Executive; delete = Owner, Manager; Technician has no access.

## Business rules
- Mobile number is unique (DB constraint) → duplicates `409`.
- Lead → Lost requires a reason (`400` otherwise); no-op status change `400`.
- Timeline entries are immutable — verified there is no mutation route.
- Note edits preserve prior versions.
- Document upload rolls back the stored file if the DB write fails; delete/replace removes the old file (no orphans).
